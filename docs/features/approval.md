# 承認と自律モード

ツールを実行する前に利用者へ確認するかどうかを決める仕組みである。**自律モードと
役割モードは名前が似ているだけの別の仕組みで、こちらは権限を決める。**

## 目的

| 満たす要件                                                                                                                   | 内容                                                                         |
| ---------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `FR-APRV-01`                                                                                                                 | 既定では、ツールの実行の前に承認を求める                                     |
| `FR-APRV-02` `FR-APRV-02a` `FR-APRV-02b` `FR-APRV-02c` `FR-APRV-02d` `FR-APRV-02e` `FR-APRV-02f` `FR-APRV-02g` `FR-APRV-02h` | 自律モードを 5 種類に定め、それぞれの範囲を決める                            |
| `FR-APRV-03` `FR-APRV-03a`                                                                                                   | 自律モードが書き換える設定を 6 つに限る                                      |
| `FR-APRV-04`                                                                                                                 | 自律モードを変えられるのは利用者だけとする                                   |
| `FR-APRV-05` `FR-APRV-05a` `FR-APRV-05b`                                                                                     | 現在の自律モードをシステムプロンプトで LLM へ伝える                          |
| `FR-APRV-06`                                                                                                                 | 画面・コマンド・キーバインドからの切り替え                                   |
| `FR-APRV-07` `FR-APRV-07a` `FR-APRV-07b`                                                                                     | 種類ごとの自動承認と、ワークスペースの外および保護対象の別扱い               |
| `FR-APRV-08` `FR-APRV-08a` `FR-APRV-08b` `FR-APRV-08c` `FR-APRV-08d`                                                         | コマンドの許可と拒否の一覧、および一致の判定                                 |
| `FR-APRV-09`                                                                                                                 | コマンドの実行を招く変数展開の検出                                           |
| `NFR-SEC-01` `NFR-SEC-02` `NFR-SEC-03` `NFR-SEC-10`                                                                          | 承認を省く範囲は利用者だけが広げられる。破壊的なコマンドは出荷時から拒否する |
| `NFR-USA-02` `NFR-USA-02a` `NFR-USA-02b` `NFR-USA-05`                                                                        | 実行する内容そのものを提示し、現在の自律モードを画面に出す                   |

ユースケースは UC-09（承認の範囲を切り替える）と UC-10（コマンドの許可と拒否を定める）。

| ---------------------------------------- | ------------------------ |

## 方式

自律モードの定義は `packages/types/src/autonomy.ts` の `AUTONOMY_PRESETS` にある。適用は
`ClineProvider.setAutonomyMode`。コマンドの判定は `src/core/auto-approval/commands.ts`。

### 5 つの自律モード

| モード      | 読み取り | 編集         | コマンド                     | MCP      | サブタスク |
| ----------- | -------- | ------------ | ---------------------------- | -------- | ---------- |
| `manual`    | 確認する | 確認する     | 確認する                     | 確認する | 確認する   |
| `autoEdit`  | 承認なし | 承認なし     | 確認する                     | 承認なし | 承認なし   |
| `auto`      | 承認なし | 承認なし     | 承認なし                     | 承認なし | 承認なし   |
| `autopilot` | 承認なし | 承認なし     | 承認なし（許可の一覧の外も） | 承認なし | 承認なし   |
| `plan`      | 承認なし | **拒否する** | **拒否する**                 | 確認する | 確認する   |

`plan` だけは承認を求めるのではなく、ツールの判定の層で拒否する。書き込みと実行の
設定は偽にしてあり、判定を回避されても自動承認は起きない。

`auto` の「承認なし」のコマンドは、許可の一覧に一致するものに限る。一覧の外のコマンドは
確認する。

### `autopilot` は利用者に確認しない

`autopilot` は、利用者が画面の前にいない前提で最後まで進めるモードである。判定は
`src/core/auto-approval/index.ts` の `checkAutopilot` にまとめてある。確認を求める場面
（ask）ごとに、次のように自動で決める。

| 場面                                           | 決め方                                                                 |
| ---------------------------------------------- | ---------------------------------------------------------------------- |
| LLM からの質問                                 | 最初の候補で即座に答える。候補が無ければ、自分で決めて進めるよう答える |
| コマンド                                       | 拒否の一覧に一致すれば拒否し、それ以外は許可の一覧の外でも実行する     |
| ワークスペースの外・保護対象への操作           | 個別の設定が許していれば実行し、許していなければ拒否する               |
| API の失敗・連続ミス・リクエスト数と費用の上限 | 続行を選ぶ                                                             |
| タスクの完了・再開                             | 利用者を待つ（止める操作ではないため）                                 |

拒否は、ツールの結果として LLM へ返る。LLM は別の方法を選んで続ける。同一の呼び出しの
繰り返しの判定（`ToolRepetitionDetector`）も行わない。**止める手段は、利用者の停止の操作だけ
である。**

LLM へは、利用者が答えないことと、質問が自動で答えられることを、システムプロンプトの
自律モードの節で伝える。

質問への自動の返事は待たずに渡す。以前は、質問の自動承認を設定で有効にすると、待機の
時間が過ぎた後に最初の候補が選ばれていた。待機の間に操作しないと勝手に進むため、廃止した。
`autopilot` 以外のモードでは、質問は必ず利用者に聞く。

### 書き換える設定を 6 つに限る

自律モードを適用したとき書き換えるのは、自動承認の有効化と、読み取り・書き込み・実行・
MCP・サブタスクの 5 つだけである。コマンドの許可と拒否の一覧、ワークスペースの外への
操作、保護対象への操作は書き換えない。**モードを切り替えただけで、
利用者が明示的に決めた範囲が黙って広がらないようにする。**

### 自律モードは利用者だけが変える

LLM から自律モードを変える経路を持たない。変えられると、破壊的なコマンドの拒否の
一覧を回避できる。

現在の自律モードは、承認の要否も `plan` の拒否も LLM からは見えない。
`src/core/prompts/sections/autonomy.ts` が唯一の伝達の経路であり、文面は
`AUTONOMY_PRESETS` の実際の値から作る。

### コマンドの一致は、長いほうを採る

許可と拒否の両方に一致した場合、一致した部分が長いほうを採る。判定は連結された
コマンドをそれぞれ取り出して行う。`&&` や `;` の後ろだけが拒否の一覧に一致する場合も拒否する。

拒否の一覧には、破壊的なコマンドの既定値を出荷時から入れる。利用者が設定を書くまで
無防備な状態を作らない。

変数展開でコマンドを埋め込む記法を検出した場合は、自動承認の設定に関わらず確認する。

## 制約

- 自律モードはツールのグループ単位でしか区別しない。ファイルの種別による制限は持たない。
- コマンドの一致は前方一致である。正規表現は使わない。
- ワークスペースの外への読み書きは、内側とは別の設定で制御する。自律モードはこれを
  書き換えない。

## 危険なところ

- **`AUTONOMY_PRESETS` を変えたら、プロンプトの文面も変える。** 文面と実際の値がずれると、
  LLM は許されていない操作を試し続ける。
- **自律モードの適用が書き換える設定を増やさない。** 増やすと、モードの切り替えで
  利用者の決めた範囲が広がる。
- 拒否の一覧の既定値を空にしない。空にすると、設定を書いていない利用者が無防備になる。
  `autopilot` では、拒否の一覧が唯一のコマンドの制限になる。
- **`autopilot` は、失敗し続けても止まらない。** 連続ミスと繰り返しの判定、リクエスト数と
  費用の上限を判定しないため、同じ失敗を繰り返す間もリクエストと費用がかかり続ける。
- **`autopilot` の判定で、人に聞く（ask）を返さない。** 返すと、利用者のいない状態で
  タスクが止まる。例外は、止める操作ではない完了と再開だけである。

## できていないこと

- 拒否の一覧は前方一致であり、同じコマンドを別の書き方で呼ばれると一致しない
  （`FR-APRV-08a`）。
- `auto` で任意のコマンドを承認なしで実行するには、利用者が許可の一覧へ `*` を書く必要がある
  （`FR-APRV-02c`）。
- `autopilot` でも、API の再試行が上限に達したときはタスクが終わる（`FR-LOOP-07b`）。
  利用者に確認するのではなく、終端のエラーとして止まる。
