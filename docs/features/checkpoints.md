# チェックポイント

ファイルを書き換えるツールの直前に、ワークスペース全体を記録する仕組みである。
**利用者の git を汚さずに記録するため、git 本体をワークスペースの外へ置く。**

## 目的

| 満たす要件                                                          | 内容                                                           |
| ------------------------------------------------------------------- | -------------------------------------------------------------- |
| `FR-CKPT-01` `FR-CKPT-01a`                                          | 編集の直前に記録する。1 回の応答につき 1 回だけ                |
| `FR-CKPT-02` `FR-CKPT-02a` `FR-CKPT-02b`                            | git 本体を外へ置き、作業ツリーだけをワークスペースへ向ける     |
| `FR-CKPT-03` `FR-CKPT-03a`                                          | 利用者の設定を引き継がず、操作先を横取りする環境変数を取り除く |
| `FR-CKPT-04` `FR-CKPT-04a`                                          | 記録から除外するもの                                           |
| `FR-CKPT-05`                                                        | 入れ子の git リポジトリの検出                                  |
| `FR-CKPT-06` `FR-CKPT-06a` `FR-CKPT-06b` `FR-CKPT-07` `FR-CKPT-07a` | 復元と差分                                                     |
| `FR-CKPT-08` `FR-CKPT-08a` `FR-CKPT-09`                             | 使うかどうかの設定と、使えないときの扱い                       |
| `NFR-SEC-11`                                                        | 記録の操作が、利用者の設定した処理を実行しない                 |
| `NFR-PERF-05`                                                       | 大きさの割に情報の少ないファイルを記録しない                   |
| `NFR-REL-01`                                                        | 記録が使えなくても、編集そのものは続行する                     |

ユースケースは UC-03（任意の時点まで戻す）。
仕組みの説明は [diff-and-checkpoints.md](../development/diff-and-checkpoints.md) の 2 節にある。

### 扱わないもの

| 対象                           | どこにあるか             |
| ------------------------------ | ------------------------ |
| 1 回の編集の差分プレビュー     | [editing.md](editing.md) |
| タスクを削除したときの後片付け | [tasks.md](tasks.md)     |

## 方式

実装は `src/services/checkpoints/` と `src/core/checkpoints/`。

### git 本体をワークスペースの外へ置く

リポジトリ本体を拡張の保存先へ置き、作業ツリーだけをワークスペースへ向ける。
ワークスペースの実ファイルを対象にコミットできるのに、ワークスペースには `.git` が
生えず、利用者の git と独立する。リポジトリはタスクごとに 1 つ作る。

### 利用者の設定を引き継がない

空のテンプレートで初期化し、フックと署名を無効にし、専用の名義でコミットする。
`GIT_DIR` や `GIT_WORK_TREE` など操作先を横取りする環境変数を取り除いた状態で git を
実行する。取り除かないと、記録の操作が利用者のリポジトリに対して動く。

### 除外はシャドウ側にだけ効かせる

除外の一覧は、シャドウリポジトリの内側の設定へ書く。ワークスペースの `.gitignore` も
尊重する。ビルドの生成物・依存パッケージ・画像と動画・大きなバイナリ・キャッシュを
外す。外さないと、編集のたびの記録が現実的な時間で終わらない。

### 復元は 2 つに分ける

| 操作         | 戻す範囲                                           |
| ------------ | -------------------------------------------------- |
| ファイルだけ | ワークスペースの実ファイル                         |
| 会話も       | 実ファイルに加えて、会話履歴をその時点まで巻き戻す |

会話を巻き戻した場合は、削除した分のトークンの消費量を集計して表示する。

## 制約

- ワークスペースの内側に別の `.git` がある場合は、機能を無効にして警告する。
  サブモジュールを含むリポジトリでは使えない。
- 記録はファイルを書き換えるツールの直前にだけ取る。コマンドの実行による変更は
  記録しない。
- git が無い環境・ワークスペースが無い場合・初期化に失敗した場合は、機能だけを
  無効にする。

## 危険なところ

- **編集そのものを止めない。** 一度でも致命的な失敗が起きたタスクでは、以降の記録を
  無効にしたうえで編集を続ける。記録の失敗で作業が止まると、機能ごと外すしかなくなる。
- 復元は実行中のタスクを止めてから行う。止めずに実行すると、復元の最中の書き込みと
  競合する。

## 確かめ方

| 何を                                   | どこで                                                               |
| -------------------------------------- | -------------------------------------------------------------------- |
| ワークスペースに `.git` を作らないこと | `src/services/checkpoints/__tests__/ShadowCheckpointService.spec.ts` |
| 環境変数を取り除いて実行すること       | 同上                                                                 |
| 入れ子のリポジトリの検出               | 同上                                                                 |
| 除外の一覧                             | `src/services/checkpoints/__tests__/excludes.spec.ts`                |
| 復元の経路                             | `src/core/webview/__tests__/checkpointRestoreHandler.spec.ts`        |

## できていないこと

- コマンドの実行による変更を記録しない（`FR-CKPT-01`）。
- 記録の保存期間を定めていない（`requirements.md` の 5.2）。
