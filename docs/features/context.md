# コンテキストの組み立てと要約

LLM へ送る内容を組み立て、長くなったら圧縮する仕組みである。システムプロンプト・
環境情報・会話履歴の 3 つを扱う。

## 目的

| 満たす要件                                                                   | 内容                                           |
| ---------------------------------------------------------------------------- | ---------------------------------------------- |
| `FR-CTX-01`                                                                  | システムプロンプトを節に分けて組み立てる       |
| `FR-CTX-02` `FR-CTX-02a` `FR-CTX-02b` `FR-CTX-02c` `FR-CTX-02d` `FR-CTX-02e` | 環境情報の付加と、その件数の上限               |
| `FR-CTX-03` `FR-CTX-03a` `FR-CTX-03b` `FR-CTX-03c`                           | 会話履歴の自動の要約と、そのしきい値           |
| `FR-CTX-04` `FR-CTX-05` `FR-CTX-06`                                          | 要約のプロンプト、送る形、ファイルの畳み方     |
| `FR-CTX-07` `FR-CTX-08`                                                      | 要約で足りない場合の切り詰めと、超過からの復帰 |
| `FR-CTX-09` `FR-CTX-10` `FR-CTX-10a`                                         | 共通の指示と、入力の整形                       |
| `NFR-PERF-03` `NFR-PERF-04`                                                  | 環境情報に上限を設け、上限に達する前に圧縮する |

ユースケースは UC-01（指示を出す）。

### 扱わないもの

| 対象                     | どこにあるか                               |
| ------------------------ | ------------------------------------------ |
| ツールの定義の組み立て   | [tools.md](tools.md)                       |
| 自律モードの節           | [approval.md](approval.md)                 |
| ルールとスキルの読み込み | [extension-points.md](extension-points.md) |

## 決めごと

システムプロンプトは `src/core/prompts/sections/` の節ごとに組み立てる。環境情報は
`src/core/environment/getEnvironmentDetails.ts` が作る。要約は `src/core/condense/`、
切り詰めは `src/core/context-management/` にある。

### 環境情報には件数の上限を置く

開いているタブ・ワークスペースのファイル・git の変更ファイルには、それぞれ上限がある。
大きなワークスペースで、環境情報だけがコンテキストウィンドウを埋めるためである。
時刻・費用・診断は、含めるかどうかを利用者が選ぶ。

### 要約は、上限に達する前に始める

しきい値はコンテキストウィンドウに対する割合で持ち、プロファイルごとに変えられる。
**上限に達してから対処すると、そのリクエスト自体が失敗する。** 要約で足りない場合は、
古い履歴を切り詰める。

### 要約のリクエストからツールの項目を外す

ツールの呼び出しと結果をそのまま送ると、接続先によってはツールの定義を要求されて
失敗する。要約は本文だけで足りるので、本文へ変換してから送る。

### 読み取り済みのファイルは定義へ畳む

要約の際、読み取ったファイルの全文は残さず、tree-sitter で抽出した定義の一覧へ
置き換える。構造は残り、量は減る。

## 制約

- しきい値には下限と上限がある。極端な値を設定できない。
- 要約そのものが 1 回の LLM のリクエストである。要約の失敗は、そのまま反復の失敗になる。
- 環境情報の上限は件数であり、文字数ではない。1 件が大きい場合は上限が効かない。

## 危険なところ

- **要約の後に履歴を巻き戻すと、要約した内容と巻き戻した内容が食い違う。**
  チェックポイントからの復元と組み合わせたときの経路を確かめる。
- 共通の指示は全タスクへ入る。長く書くと、毎回のリクエストがその分だけ重くなる。

## 確かめ方

| 何を                       | どこで                                                         |
| -------------------------- | -------------------------------------------------------------- |
| しきい値で要約が始まること | `src/core/condense/__tests__/index.spec.ts`                    |
| 要約のリクエストの形       | 同上                                                           |
| 要約の後の巻き戻し         | `src/core/condense/__tests__/rewind-after-condense.spec.ts`    |
| 入れ子の要約               | `src/core/condense/__tests__/nested-condense.spec.ts`          |
| 環境情報の組み立て         | `src/core/environment/__tests__/getEnvironmentDetails.spec.ts` |

## できていないこと

- 環境情報の上限が件数であり、1 件が大きい場合に効かない（`FR-CTX-02b`）。
- 要約に失敗した場合の代替の経路が、切り詰めだけである（`FR-CTX-07`）。
