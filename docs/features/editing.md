# ファイルの編集と差分プレビュー

LLM がファイルを書き換えるときの経路である。**変更は承認を得るまでディスクへ
書き込まない。** 差分ビューに提示し、承認されたときだけ保存する。

## 目的

| 満たす要件                                                                         | 内容                                                     |
| ---------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `FR-EDIT-01` `FR-EDIT-02`                                                          | 全文の書き込みと、検索置換ブロックによる部分の編集       |
| `FR-EDIT-03` `FR-EDIT-04` `FR-EDIT-04a` `FR-EDIT-04b`                              | 確定まで書き込まず、差分ビューへ提示する                 |
| `FR-EDIT-05` `FR-EDIT-05a`                                                         | 承認で保存し、拒否で元へ戻す                             |
| `FR-EDIT-06` `FR-EDIT-06a` `FR-EDIT-06b` `FR-EDIT-06c`                             | 編集で新しく出たエラーだけを LLM へ返す                  |
| `FR-EDIT-07` `FR-EDIT-08`                                                          | 利用者が手で加えた変更の検出と、末尾の改行の保持         |
| `FR-EDIT-09` `FR-EDIT-09a` `FR-EDIT-09b` `FR-EDIT-09c` `FR-EDIT-09d` `FR-EDIT-09e` | 検索置換ブロックの当て方                                 |
| `FR-EDIT-10`                                                                       | チャットへ出す差分の整形と行数の集計                     |
| `FR-EDIT-11`                                                                       | 差分ビューを開かずに直接書き込む経路                     |
| `FR-EDIT-50` `FR-EDIT-50a`                                                         | `.agentprotected` による、自動承認をすり抜けさせない保護 |
| `NFR-SEC-04`                                                                       | 本製品自身の設定に関わるファイルは、必ず利用者へ確認する |
| `NFR-REL-02` `NFR-REL-03`                                                          | 拒否で元へ戻る。当たらなかった編集でファイルを壊さない   |

ユースケースは UC-02（差分を読んで承認または破棄する）と UC-04（新しいエラーを直させる）。
仕組みの説明は [diff-and-checkpoints.md](../diff-and-checkpoints.md) の 1 節にある。

### 扱わないもの

| 対象             | どこにあるか                     |
| ---------------- | -------------------------------- |
| 編集の直前の記録 | [checkpoints.md](checkpoints.md) |
| 読み取りの可否   | [file-access.md](file-access.md) |
| 自動承認の設定   | [approval.md](approval.md)       |

## 決めごと

実装は `src/core/tools/` の編集ツール群と `src/integrations/editor/DiffViewProvider.ts`。
検索置換の適用は `src/core/diff/strategies/multi-search-replace.ts`。

### 左側は実ファイルではない

差分ビューの左側は、専用のスキームを持つ仮想の読み取り専用ドキュメントである。元の
内容を URI へ埋め込み、拡張が登録した提供者が返す。実ファイルではないので、左側が
書き換わることがない。右側だけが実ファイルである。

### 保護と除外は役割が違う

| 仕組み            | 何をするか                                   |
| ----------------- | -------------------------------------------- |
| `.agentignore`    | アクセスそのものを拒む。編集を始めない       |
| `.agentprotected` | アクセスは許すが、自動承認をすり抜けさせない |

`.agentprotected` の対象は決め打ちのパターンで、本製品自身の設定に関わるファイル群を
含む。これらを自動で書き換えられると、以降の承認の判定そのものが変わる。

### 当たらなかったら書き換えない

検索置換ブロックが当たらなかった場合、そのブロックを記録して LLM へ返し、
ファイルは書き換えない。部分的に当たった状態で保存すると、元の内容へ戻せない。

位置の探索は、指定された行での厳密な一致を先に試し、外れたら周辺を中央から外へ
広げて探す。一致の判定には編集距離を使い、しきい値は既定で完全一致とする。

## 制約

- 診断の収集は、警告を除いてエラーだけを対象とする。警告まで返すと、編集と関係のない
  指摘が積み上がる。
- 収集の前に待機を置く。静的検査の結果が出そろう前に読むと、増えたエラーを検出できない。
- 実験機能を有効にすると差分ビューを開かないが、承認と診断の収集は変えない。

## 危険なところ

- **拒否したときの復元は、エラーの経路が 2 つある。** 同期の例外は外側で、非同期の
  失敗は内側で受ける。前提の崩れた状態で呼ぶと、分かりにくい形で失敗する。
- 新しい編集ツールを足すとき、差分ビューの 4 つの操作（開く・流し込む・確定・破棄）を
  すべて通さないと、拒否したときにファイルが中途の状態で残る。

## できていないこと

- 保護の対象は決め打ちのパターンであり、利用者が足せない（`FR-EDIT-50a`）。
- 復元のエラーの経路が二重である（`FR-EDIT-05`）。
