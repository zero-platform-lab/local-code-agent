# 拡張ポイント（ルール・スキル・スラッシュコマンド）

利用者が、コードを変えずに指示を足せる場所である。3 つあり、いずれもプロジェクトと
利用者のホームの双方から読み込む。

## 目的

| 満たす要件                                                                   | 内容                                       |
| ---------------------------------------------------------------------------- | ------------------------------------------ |
| `FR-EXT-01` `FR-EXT-01a`                                                     | 規則のファイルをシステムプロンプトへ加える |
| `FR-EXT-02` `FR-EXT-02a` `FR-EXT-02b` `FR-EXT-02c`                           | スキルの探索と、名前およびモードの制約     |
| `FR-EXT-03` `FR-EXT-03a` `FR-EXT-03b`                                        | スラッシュコマンドと、探索の範囲の制限     |
| `FR-EXT-04`                                                                  | 実験的な機能の個別の有効化                 |
| `FR-EXT-05` `FR-EXT-05a` `FR-EXT-05c` `FR-EXT-05d` `FR-EXT-05e`              | git リポジトリからスキルを取得する         |
| `FR-EXT-05b` `FR-EXT-05b1` `FR-EXT-05b2` `FR-EXT-05b3`                       | 取得に使う proxy                           |
| `FR-EXT-05f` `FR-EXT-05f1` `FR-EXT-05f2`                                     | ほかのツールと共有する場所への複製         |
| `FR-EXT-06` `FR-EXT-06a` `FR-EXT-06b` `FR-EXT-06c` `FR-EXT-06d` `FR-EXT-06e` | HTTPS の取得元の資格情報                   |

ユースケースは UC-19（プロジェクト固有の指示を与える）。

## 方式

実装は `src/services/agent-config/`（規則）・`src/services/skills/`（スキル）・
`src/services/command/`（スラッシュコマンド）。

### 3 つの違い

|                    | 読み込む時点   | LLM へ渡る形             |
| ------------------ | -------------- | ------------------------ |
| 規則               | 毎回           | システムプロンプトの一部 |
| スキル             | 呼び出したとき | ツールの結果             |
| スラッシュコマンド | 呼び出したとき | ツールの結果             |

規則は毎回のリクエストへ入るので、量が直接コストになる。手順を書くならスキルへ置く。

### 探索の範囲から出さない

スラッシュコマンドの探索では、相対パスによる範囲の逸脱とシンボリックリンクを拒否する。
拒否しないと、ワークスペースの外のファイルを読み込ませられる。

### スキルの名前は外部の仕様に合わせる

名前の文字と長さの制約は agentskills.io の仕様に従う。ほかのツールが置いたスキルを
そのまま読めるようにするためである。

スキルは利用できる役割モードを指定できる。指定が無い場合はすべてのモードで使える。

### 取得したものと、手で置いたものを、別のディレクトリに分ける

取得したリポジトリは `~/.agent/skill-sources/<ホスト名>/<パス>/` へ置く。**そのディレクトリを
探索先の一覧へ足す。** `getSkillsDirectories()` は既に 4 系統を並べているので、そこへ
加えるだけで済む。

置き場所は URL から機械的に決める（`FR-EXT-05c1`）。利用者が名前を付けないので、同じ
URL を 2 回登録しても同じ場所になり、重複を弾く処理が要らない。

```
~/.agent/skill-sources/gitlab.example.com/platform/skills/
```

`https://gitlab.example.com/platform/skills.git` と
`git@gitlab.example.com:platform/skills.git` は同じ場所になる。

受け付けない URL が 2 つある（`FR-EXT-05c2`）。`..` を含むものと、パスに使えない文字を
含むものである。

**`~/.agent/skills` へは clone しない。** 手で置いたスキルと同じ場所に混ざると、取得の
たびに「どれを消してよいか」を判別できなくなる。場所を分ければ、**取得の処理が
`skills/` に触れる経路そのものが無くなる**（`FR-EXT-05e`）。取得元を消すのも、
ディレクトリを 1 つ消すだけでよい。

**シンボリックリンクは使わない。** Windows では作成に管理者権限か開発者モードが要り、
このリポジトリには Windows を検証する手段が無い（`requirements.md` の 5.2）。探索先を
足すほうが、同じことを制約なしに実現できる。

探索先の一覧は後ろほど優先されるので、`skill-sources` を既存の 4 系統より前に置く。
**同じ名前なら、手で置いたものが勝つ。**

### 資格情報は本製品で持たず、git の保管庫へ預ける

HTTPS の private な取得元には資格情報が要る。**画面で聞いて、`git credential approve` へ
標準入力で渡し、OS の保管庫に覚えさせる**（`FR-EXT-06` `FR-EXT-06a`）。以降の clone と
pull は、こちらが何もしなくても通る。

**本製品は値を保持しない。** 持たなければ、書き出しから除く処理も、記録から伏せる処理も、
保存先を守る処理も要らない。

渡し方には制約がある（`FR-EXT-06b`）。

| 渡し方                      | どこに残るか                                          |
| --------------------------- | ----------------------------------------------------- |
| `https://user:token@host/…` | `.git/config` の remote に保存される                  |
| `-c http.extraHeader=…`     | `ps` から読める。プロセスの引数は他の利用者にも見える |
| 環境変数                    | 子プロセスの環境に残る                                |
| **標準入力**                | **どこにも残らない**                                  |

**`credential.helper` が未設定のことがある。** Linux では既定で何も設定されておらず、その
場合 `approve` は黙って何もしない。預けられないまま次の取得が失敗するので、設定されて
いないことと設定の方法を示す（`FR-EXT-06c`）。macOS と Windows には既定の保管庫がある。

`GIT_ASKPASS` を配る案は採らない。git は指定されたものを実行ファイルとして起動するため、
POSIX 用と Windows 用の 2 本を配布物へ入れることになる。**Windows を検証する手段が無い**
ので、片方は確かめられないまま出すことになる。

資格情報が無いときは入力を待たずに失敗させる（`FR-EXT-06d`）。待つと、画面の無いところで
git が止まったままになる。

SSH の取得元では、この仕組みを使わない。鍵は git と ssh が扱う。

### proxy は解決だけを共有し、転送は git に任せる

`resolveEffectiveProxy` で URL を決め、`simpleGit({ config: ["http.proxy=..."] })` として
渡す（`FR-NET-13a`）。**dispatcher は通らない。** clone はスマート HTTP のやり取りを
自前で実装することになるので、git に任せる。

SOCKS では名前の解決を proxy 側で行う（`FR-NET-12a1`）。git の `http.proxy` は
`socks5://` をクライアント側の解決として扱うため、**渡す前に `socks5h://` へ書き換える**
（`FR-EXT-05b2`）。拡張の dispatcher はホスト名をそのまま SOCKS へ渡すので、これで
両方の経路がそろう。

**SSH の取得元では `http.proxy` が完全に無視される。** 設定しても何も起きず、エラーも
出ない。黙って無視すると切り分けができないので、利用者へ伝える（`FR-EXT-05b3`）。

## 制約

- 組み込みのスキルは持たない。仕組みだけを持つ。
- 組み込みのスラッシュコマンドは 1 件だけである。
- スラッシュコマンドを LLM から呼べるのは、実験的な機能を有効にした場合に限る。

## 危険なところ

- **規則のファイルを長くすると、毎回のリクエストが重くなる。** 量の上限を持たない。
- 探索の範囲の検査を外すと、ワークスペースの外を読める。新しい探索の経路を足すときは、
  同じ検査にかける。
