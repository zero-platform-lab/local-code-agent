# 表示言語

画面の表示言語を日本語と英語から選ぶ。拡張ホストと画面の双方に翻訳を持つ。

## 目的

| 満たす要件   | 内容                                 |
| ------------ | ------------------------------------ |
| `FR-I18N-01` | 表示言語を日本語と英語の 2 つとする  |
| `FR-I18N-02` | 拡張ホストと画面へ同じ設定で適用する |
| `FR-I18N-03` | 翻訳の欠落を品質ゲートで検出する     |
| `NFR-USA-01` | 利用者が表示言語を選べる             |

ユースケースは UC-21（表示言語を選ぶ）。

### 扱わないもの

| 対象                       | どこにあるか             |
| -------------------------- | ------------------------ |
| LLM へ送るプロンプトの言語 | [context.md](context.md) |

## 方式

翻訳は `src/i18n/locales/` と `webview-ui/src/i18n/locales/` の 2 か所に置く。
拡張ホストの通知と、画面の文言で、読み込む側が違うためである。

VS Code の定義に載せる文言は、`src/package.nls.json` と `src/package.nls.ja.json` に置く。

**言語を 2 つに絞ったのは、Roo Code の多言語のうち、確かめられるのがこの 2 つだけだからで
ある。** 確かめられない翻訳を置くと、誤った文言が出たまま残る。

## 制約

- LLM へ送るプロンプトは英語である。表示言語の設定は、これを変えない。
- 翻訳の欠落は品質ゲートで検出するが、訳の誤りは検出しない。

## 危険なところ

- 文言を足すとき、2 か所のどちらへ置くかを間違えると、実行時に鍵がそのまま表示される。
- VS Code の定義の文言を足すときは、`package.nls.json` の側も併せて足す。

## 確かめ方

| 何を               | どこで                                                        |
| ------------------ | ------------------------------------------------------------- |
| 翻訳の欠落         | `scripts/find-missing-translations.js`（品質ゲートの 1 段目） |
| 読み込みと切り替え | `src/i18n/__tests__/index.spec.ts`                            |

## できていないこと

- 訳の誤りを検出する手段が無い（`FR-I18N-03`）。
