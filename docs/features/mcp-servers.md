# MCP サーバ連携

外部のプロセスが公開するツールとリソースを、LLM に使わせる仕組みである。設定ファイルに
書いたサーバへ接続し、そのツールを LLM へ提示し、呼び出しを中継する。

## 目的

| 満たす要件                                                    | 内容                                                     |
| ------------------------------------------------------------- | -------------------------------------------------------- |
| `FR-MCP-01` `FR-MCP-02` `FR-MCP-02a` `FR-MCP-02b` `FR-MCP-03` | 2 層の設定と、3 種類の接続の方式                         |
| `FR-MCP-04` `FR-MCP-05` `FR-MCP-05a` `FR-MCP-05b` `FR-MCP-06` | 設定の検証、変更の反映、再接続の判定                     |
| `FR-MCP-07` `FR-MCP-08`                                       | 画面へ渡す設定と、接続しないサーバの追跡                 |
| `FR-MCP-09` `FR-MCP-09a` `FR-MCP-09b` `FR-MCP-10`             | LLM への提示と、モードによる遮断                         |
| `FR-MCP-11` `FR-MCP-12` `FR-MCP-13` `FR-MCP-14`               | 呼び出しの中継、ツール単位の設定、上限の時間、件数の警告 |
| `FR-MCP-15` `FR-MCP-16`                                       | 全体の有効化と、画面からの操作                           |
| `NFR-SEC-08`                                                  | 展開後の値を画面へ送らない                               |
| `NFR-SEC-12`                                                  | リモートのサーバへは、利用者が設定した場合にだけ接続する |

ユースケースは UC-08（外部のツールサーバを使わせる）と UC-20（サーバを登録する）。
仕組みの説明は [mcp.md](../development/mcp.md) にある。

## 方式

実装は `src/services/mcp/`。判断は純関数へ切り出し、副作用の順序だけを `McpHub` が持つ。

### ツールはサーバとツールの組ごとに提示する

1 つの汎用のツールとして渡すのではなく、サーバとツールの組ごとに個別の定義として
LLM へ渡す。名前は長さの上限に収まるよう変換し、重複したときは先に登録したものを残す。
変換した名前は、実名へ復元できるよう対応を保持する。

### 画面へ渡す設定は、変数を展開する前の宣言とする

サーバの設定は画面へそのまま送られる。展開後を載せると、環境変数に置いた秘密情報が
画面へ渡る。展開後が要るのは接続の生成だけで、どこにも保持しない。

### 再接続の判定も、展開前の宣言で行う

展開後で比べると、環境変数を含む設定が毎回「変わった」と判定される。宣言どうしを
比べる。

### 本製品自身の書き込みでは再接続しない

上限の時間の変更やツール単位の設定の切り替えは、本製品が設定ファイルへ書き込む。
書き込みの間は変更の検出を止める。止める時間は、変更の検出の待機をまたぐ長さにする。

## 制約

- 全体の有効化の設定が未定義のときは、有効として扱う。無効になるのは、利用者が
  明示的に無効にした場合だけである。
- 現在の役割モードが mcp グループを持たない場合、MCP のツールは 1 件も提示しない。
- 有効なツールの数がしきい値を超えると警告する。多すぎると LLM の選択の精度が下がる。
- 設定の層は 2 つで、プロジェクトの層が先に来る。

## 危険なところ

- **接続先のサーバは、任意のコードの実行と同等の権限を持つ。** 信頼できないサーバを
  繋がないことは、利用者の判断に委ねている（`README.md`）。
- 展開後の値を画面へ送る実装へ戻すと、秘密情報が漏れる。
- 変更の検出を止める時間を短くすると、本製品自身の書き込みでサーバが再起動する。

- 実際に繋ぐサーバを決めていない（`requirements.md` の 5.2）。
