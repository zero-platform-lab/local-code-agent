# ファイルごとの伏せ字の保管（ファイル対応表）

## 目的

ファイル対応表を入にすると、エージェントが読んだファイルの伏せ字と元の値の対応を、本製品の
起動をまたいで保持する（`FR-PII-24`）。既定は切で、右下のトグルで入/切を切り替える。
**ファイル本体は保存しない。**

[pii-masking.md](pii-masking.md) のセッション対応表は、伏せ字と元の値の対応を
**記憶内だけに持ち、本製品を終えると捨てる**（`FR-PII-20b`）。この決めごとで送受信の一往復は
可逆になるが、起動をまたぐと同じ対応は残らない。

残らないことで、起動をまたぐと伏せ字がぶれる。同じファイルの同じ氏名が、前回と別の
伏せ字になる。長い作業を後日に再開すると、モデルから見た伏せ字が前回と食い違う。ファイル対応表は
その対応を残し、次の起動でも同じ伏せ字を使えるようにする。

| 要件                      | 扱う範囲                                   |
| ------------------------- | ------------------------------------------ |
| `FR-PII-24`〜`FR-PII-24f` | 何を、どこに、どう残すか                   |
| `FR-PII-25` `FR-PII-25a`  | 読んだファイルの保存と取り込み             |
| `FR-PII-26`〜`FR-PII-26b` | 保持期限と、消えた・移したファイルへの追従 |
| `FR-PII-27` `FR-PII-27a`  | 消去の操作と、消す前の確認                 |
| `FR-PII-28`               | 上限と、上限に達したときの扱い             |

## 方式

**入/切は 1 つで持つ**（`piiMasking.fileMapping.enabled`）。会話の画面の右下、シークレットモードの
隣のトグルで切り替える。入にすると、エージェントが読んだファイルの対応を保存する。切にすると
保存せず、従来どおり記憶内だけで伏せる。

**当初はファイルごとに有効化する形にしたが、全体の入/切へ作り直した。** ファイルごとにした理由は、
触ったファイルを勝手に残さないためだった。だが同じ PII は元のファイルやタスク履歴にもあり、保持期限と上限で縛るので、
読んだファイルを一律に残しても害は小さい。ファイルごとの操作（有効化・無効化・状態）は、得られる
ものの割に画面と概念を増やしていた。

**保存するのは対応表だけで、ファイル本体は残さない**（`FR-PII-24a`）。ファイル対応表は「送る内容の
伏せ字を、起動をまたいで安定させる」ものであって、ファイルの秘匿保管ではない。対象はファイルの
識別子（ワークスペースフォルダの番号と相対パス）ごとに分ける。

**対応表を平文の JSON で置く**（`FR-PII-24b`）。同じ PII は、ワークスペースのファイルにも
タスクの履歴（[tasks.md](tasks.md)）にも平文であるので、対応表だけを暗号化しても守りは上がらず、
鍵の管理や喪失（読めなくなる）や非可搬という代償だけが残る。だから A の履歴・設定と揃えて平文で
置く。保存先はワークスペース固有の領域で、書き込みは一時ファイルへ書いてから置き換える。途中で
壊れた JSON を残さないためである。壊れた・版が違うときは、誤った値ではなく失敗を出す。

**保管ディレクトリに `.gitignore` を置く**（`FR-PII-24c`）。保存先は既定ではワークスペースの外
（拡張のワークスペース固有ストレージ）だが、`customStoragePath` などでリポジトリ内を指すことがある。
平文の対応表がコミットされないよう、保管ディレクトリへ「すべて無視」の `.gitignore` を置く。

**保管ルートは設定で選べる**（`FR-PII-24d`）。`piiMasking.fileMapping.root` に絶対パスを書くと、その下に
ワークスペースごとの区画（識別子のハッシュ）を作って対応表を置く。空なら既定の拡張専用ストレージ
（ワークスペースの外）を使う。絶対パスでなければ使わず、既定へ戻して知らせる。

**ルートがワークスペース内を指すときは警告する**（`FR-PII-24e`）。対応表には元の値が入るので、
ワークスペースの中に置くと、エージェントがそれを読んで LLM へ送る経路ができる。利用は続けるが、
外の置き場所を促す。

**保管領域はエージェントのファイルツールから隠す**（`FR-PII-24f`）。警告だけでは、ワークスペース内に
置いた平文の対応表を、モデルが `read_file` や `codebase_search` で読めてしまい、第 2 層が切のときは値が
素通りする。そこで、対応表の保管領域（対応表・一時ファイル・`.gitignore`）を、検索・読み取り・書き込みの
どれからも常に外す。置き場所が外（既定）でも中でも同じ扱いにする。

**入のとき、読んだファイルの対応を保存する**（`FR-PII-25`）。本製品でファイルの中身が伏せ字に
かかる関所は、送信の直前に会話全体を伏せる 1 か所である（[pii-masking.md](pii-masking.md) の
`maskConversation`）。`function_call_output` はどのファイル由来かを持たないので、同じ call_id の
`read_file` 呼び出しの引数からパスを引いて紐付ける。無ければ作り、あれば足し合わせる。

**保存済みの対応は、次に同じファイルを読むとき今回のセッション対応表へ取り込む**（`FR-PII-25a`）。
取り込みで、同じ元の値には前回と同じ伏せ字を割り当てる。番号が衝突するときは今回の番号へ
そろえる。これで起動をまたいでも伏せ字がぶれない。

**最終利用から 30 日を既定の保持期間とし、0 日は時間による期限なしを表す**（`FR-PII-26`）。
本製品の起動時と対応表の利用前に対象ファイルの存在を確認し、恒久的に消えたと分かったファイルの
対応表は削除する。存在を確認できないときは保持する（`FR-PII-26a`）。誤って消すより残すほうが
害が小さいためである。VS Code が通知するファイルの移動・改名・削除には追従し、対応表の識別子を
移すか削除する（`FR-PII-26b`）。

**消去は、利用者が選んだものだけを消す**（`FR-PII-27`）。選んだ複数のファイル、または全ファイル対応表と
セッション対応表を消せる操作を設ける。消す前に対象のファイル数と対応数を示して確認し、確認したものだけを
消し、対象外は変更しない（`FR-PII-27a`）。

**上限に達したら、黙って捨てず理由を示して失敗する**（`FR-PII-28`）。対応表のファイル数
（既定 100）、ファイルごとの対応数（既定 1000）、全体のバイト数（既定 5 MiB）に上限を設ける。
0 は無制限を表す。上限は設定で変えられる。黙って古いものを捨てると、戻せると思っていた対応が
消えるためである。

## 制約

- **対応表は平文である。** 平文の PII のコピーがもう 1 つ増える。ただし同じ PII は元のファイルにも
  タスク履歴にもあるので、守りの水準は変わらない。コミットは `.gitignore` で防ぐ。
- **切のときは残らない。** 従来どおり、プロセスが終われば対応は消える。
- **ファイル本体は保存しない。** 残すのは伏せ字と元の値の対応表だけである。

## 危険なところ

- **対応表には伏せる前の生の PII が平文で入る。** 同じ PII は元のファイルやタスク履歴にもあるので
  水準は変わらないが、保管ディレクトリが git 配下に来たときのコミットは `.gitignore` で防ぐ。
- **入のとき、読んだファイルは一律に残る。** ファイルごとに選べないので、切り忘れると触った
  ファイルの対応がたまり続ける。保持期限と上限で縛り、消去の操作を用意する。
- **識別子はワークスペース相対である。** フォルダの番号と相対パスで作るので、ワークスペースの
  構成（フォルダの順や数）が変わると、同じファイルでも別の識別子になり得る。
- **ツール引数は実行の直前に元へ戻す。** 保存済みの対応と今回の番号が衝突したまま戻すと、別の
  文字列になる。取り込みのときに番号をそろえる（`FR-PII-25a`）。
- **保管ルートをワークスペース内へ向けると危うい。** 対応表を読んで送る経路ができる。設定時に警告し、外を促すが、利用は止めない（`FR-PII-24e`）。

## 確かめ方

- 入 → 本製品を再起動 → 同じファイルで同じ伏せ字になることを試験する。切のときは保存も取り込みも
  しないことを試験する。
- 右下のトグルが `piiMasking.fileMapping.enabled` を入/切し、ほかの設定を巻き添えにしないことを試験する。
- 保管ルートを絶対パスにすると、その下のワークスペース区画へ置くこと、空なら既定を使うこと、ワークスペース内や相対パスでは警告することを試験する。
- 壊れた JSON は `corrupt`、版が違えば `unsupported` として失敗すること、保管ディレクトリに
  `.gitignore` を置くことを試験する。
- 保持期限を過ぎた対応と、消えたファイルの対応が削除されること、移動・改名に追従することを
  試験する。時計は偽物を使い、進み続ける形にする。
- 上限に達したとき、黙って捨てず理由を出すことを試験する。
- 消去は、選んだものだけを消し、確認を断れば何も変えないことを試験する。

## できていないこと

- **保存の対応づけは `read_file` だけである。** 一覧・検索（`list_files` `search_files`
  `codebase_search`）や書き込み系のツールは、1 つのファイルの内容とは言えないので対応表に
  結びつけない。
- **右クリックの伏せ字（`maskEditor`）は、まだ対応表へ保存しない。** エージェントの読み取り
  （送信経路）では効くが、右クリックでその場で伏せた新しい対応は、次の起動へは残らない。
- **実際の VS Code で右下トグルを押す往復は、手では確かめていない。** 送信経路の保存/取り込みと、
  再起動をまたいで伏せ字が安定することは、実ディスクを通す統合試験で固定している
  （`src/services/pii/__tests__/fileMappingRoundTrip.spec.ts`）。残るのは、実際の拡張ホストでの
  画面操作の確認である。
