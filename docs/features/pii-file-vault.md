# ファイルごとの伏せ字の保管（File Vault）

## 目的

伏せ字と元の値の対応を、利用者が選んだファイルについてだけ、本製品の起動をまたいで
保持する（`FR-PII-24`）。

[pii-masking.md](pii-masking.md) の Session Vault（対応表）は、伏せ字と元の値の対応を
**記憶内だけに持ち、本製品を終えると捨てる**（`FR-PII-20b`）。プロセスの間は全体で 1 つを
共有し、ファイルには結びつけない。この決めごとで**送受信の一往復は可逆になる**が、起動を
またぐと同じ対応は残らない。

残らないことで 2 つを損している。

- **起動をまたぐと伏せ字がぶれる。** 同じファイルの同じ氏名が、前回と別の伏せ字になる。
  長い作業を後日に再開すると、モデルから見た伏せ字が前回と食い違う。
- **ファイル単位の出し入れができない。** プロセスが終わると全部消えるので、あとから
  特定のファイルだけ思い出す、特定のファイルだけ忘れる、ができない。

File Vault は、利用者が明示的に有効化したファイルについてだけ、対応を暗号化して残し、
次の起動でも同じ伏せ字を使えるようにする。**ファイル本体は保存しない。**

| 要件                      | 扱う範囲                                     |
| ------------------------- | -------------------------------------------- |
| `FR-PII-24`〜`FR-PII-24c` | 何を、どこに、どう暗号化して残すか           |
| `FR-PII-25` `FR-PII-25a`  | 有効化したファイルを扱うときの追記と取り込み |
| `FR-PII-26`〜`FR-PII-26b` | 保持期限と、消えた・移したファイルへの追従   |
| `FR-PII-27` `FR-PII-27a`  | 消去の操作と、消す前の確認                   |
| `FR-PII-28`               | 上限と、上限に達したときの扱い               |

## 方式

**既定で無効とし、ファイルごとに利用者が有効化する**（`FR-PII-24`）。有効化は、いま開いて
いるファイルに対して行う。本製品は常時動き、ツールで多数のファイルを自律的に読み書きする。
触れたファイルを残すかを本製品が勝手に決めると、**利用者が見ていないファイルの生の PII まで、
大量にディスクへ置く**ことになる。だから「このファイルを残す」という明示の操作を区切りにし、
有効化していないファイルには一切書かない。プロセスが終われば消える従来のままである。

**保存するのは対応表だけで、ファイル本体は残さない**（`FR-PII-24a`）。File Vault は「送る内容の
伏せ字を、起動をまたいで安定させる」ものであって、ファイルの秘匿保管ではない。対象はファイルの
識別子（ワークスペースフォルダの番号と相対パス）ごとに分ける。

**対応表は生の PII を含むので、暗号化して置く**（`FR-PII-24b`）。中身と改竄検知を同時に行う
AES-256-GCM を使い、鍵は 32 バイトの乱数として OS の秘匿保管（SecretStorage）に持つ。**暗号文の
ファイルには鍵を入れない。** 保存先はワークスペース固有の領域で、書き込むたびに新しい 12 バイトの
値（ノンス）を作り、版と用途を固定文字列（AAD）として認証タグへ結びつける。書き込みは一時ファイル
へ書いてから置き換える。途中で壊れた暗号文を残さないためである。

**鍵はこの機械の外へ出ない。持ち出せないことを前提とする**（`FR-PII-24c`）。本製品は設定の
書き出しで暗号化を採らなかった。鍵が機械の秘匿保管に依るとその機械でしか復号できず、書き出しの
用途に使えないためである（[tasks.md](tasks.md)）。File Vault は逆に「持ち出さず、この機械の中で
守る」が目的なので、この機械依存を前提として許容する。鍵を失うと以後は復号できず、その保管庫は
戻せない。その旨を操作の前に示す。

**有効化したファイルを扱うたびに、対応をそのファイルの保管庫へ追記する**（`FR-PII-25`）。
本製品で伏せ字を割り当てる経路は 2 つある。1 つは送信の直前に会話全体を伏せる本流
（[pii-masking.md](pii-masking.md) の `maskConversation`。ツールが読んだ内容・書こうとする内容・
選択範囲・端末出力がここに集まる）。もう 1 つは、利用者が右クリックで開いているファイルの値を
その場で置き換える操作である（`FR-PII-11`、`maskEditor`）。どちらも同じ Session Vault の採番を
使う。この 2 つの経路にファイルの識別子を渡し、有効化したファイルのぶんだけ追記する。有効化して
いないファイルには何も書かない。

**保存済みの対応は、次に同じファイルを扱うとき今回の Session Vault へ取り込む**（`FR-PII-25a`）。
取り込みで、同じ元の値には前回と同じ伏せ字を割り当てる。番号が衝突するときは今回の番号へ
そろえる。これで起動をまたいでも伏せ字がぶれない。

**最終利用から 30 日を既定の保持期間とし、0 日は時間による期限なしを表す**（`FR-PII-26`）。
本製品の起動時と保管庫の利用前に対象ファイルの存在を確認し、恒久的に消えたと分かったファイルの
保管庫は削除する。存在を確認できないときは保持する（`FR-PII-26a`）。誤って消すより残すほうが
害が小さいためである。VS Code が通知するファイルの移動・改名・削除には追従し、保管庫の識別子を
移すか削除する（`FR-PII-26b`）。

**消去は、利用者が選んだものだけを消す**（`FR-PII-27`）。Session Vault、いま開いているファイル、
選んだ複数のファイル、全 File Vault を、個別または一括で消せる操作を設ける。消す前に対象の
ファイル数と対応数を示して確認し、確認したものだけを消し、対象外は変更しない（`FR-PII-27a`）。

**上限に達したら、黙って捨てず理由を示して失敗する**（`FR-PII-28`）。保管庫のファイル数
（既定 100）、ファイルごとの対応数（既定 1000）、全体のバイト数（既定 5 MiB）に上限を設ける。
0 は無制限を表す。上限は設定で変えられる。黙って古いものを捨てると、戻せると思っていた対応が
消えるためである。

## 制約

- **この機械の外では復号できない。** 鍵は機械の秘匿保管にあり、外へ出ない。保管庫のファイルを
  別の機械へ運んでも読めない。
- **鍵を失うと恒久的に戻せない。** 利用者が秘匿保管の項目を消すと、既存の保管庫は復号できない。
- **有効化していないファイルは残らない。** 従来どおり、プロセスが終われば対応は消える。
- **ファイル本体は暗号化しない。** 残すのは伏せ字と元の値の対応表だけである。ファイルそのものの
  秘匿保管の用途には使えない。

## 危険なところ

- **対応表には伏せる前の生の PII が入る。** 暗号化と、鍵を暗号文から分けることが要る。どちらかを
  外すと、いちばん秘匿すべき値が平文でディスクに残る。
- **関所を 1 つでも漏らすと、伏せ字が黙ってぶれる。** 有効化したファイルなのに追記されず、次の
  起動で別の伏せ字になる。ファイルの識別子を渡す経路は、`maskConversation` の item 種別
  （読んだ内容・書く内容・選択範囲）と、右クリックの `maskEditor` を、それぞれ確かめる。
- **識別子はワークスペース相対である。** フォルダの番号と相対パスで作るので、ワークスペースの
  構成（フォルダの順や数）が変わると、同じファイルでも別の識別子になり得る。
- **ツール引数は実行の直前に元へ戻す。** 保存済みの対応と今回の番号が衝突したまま戻すと、別の
  文字列になる。取り込みのときに番号をそろえる（`FR-PII-25a`）。

## 確かめ方

- 有効化 → 本製品を再起動 → 同じファイルで同じ伏せ字になることを試験する。
- 有効化・無効化・全消去・一覧からの消去のそれぞれで、**利用者が断ったときに何も変わらない**
  ことを固定する（断ったのに消える／消したのに残る、をどちらも起こさない）。
- 暗号文が鍵無しでは読めないこと、改竄すると `corrupt` として失敗すること、版が違えば
  `unsupported` になることを試験する。
- 保持期限を過ぎた対応と、消えたファイルの対応が削除されること、移動・改名に追従することを
  試験する。時計は偽物を使い、進み続ける形にする。
- 上限に達したとき、黙って捨てず理由を出すことを試験する。

## できていないこと

- **実装は未着手。** これは設計である。要件 `FR-PII-24`〜`FR-PII-28` は `requirements.md` に
  加えるが、対応するコードと試験はまだ無い。
- **ファイル内容の関所へ識別子を渡す配線が要る。** いまの `maskConversation` は対応をファイルに
  結びつけていない。これを足すまで、追記と取り込みは動かない。
- **別の機械への持ち出しはできない。** 鍵が機械に依るためで、これは設計上の制約である。
