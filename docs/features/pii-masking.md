# 個人情報の伏せ字

## 目的

LLM へ送る内容から、個人情報と社名を伏せ字へ置き換える（`FR-PII-01`）。

本製品はワークスペースのファイルの中身を LLM へ送る（`NFR-PRV-04`）。隔離された環境で
使う前提だが、それでも送りたくない値がある。氏名、メールアドレス、顧客の社名、社内の
ホスト名である。

| 要件                                                                                    | 扱う範囲                             |
| --------------------------------------------------------------------------------------- | ------------------------------------ |
| `FR-PII-01` `FR-PII-01a` `FR-PII-01b` `FR-PII-01c`                                      | 切り替えと、件数の提示               |
| `FR-PII-02` `FR-PII-02a` `FR-PII-02b`                                                   | 可逆な置き換えと、対応表の寿命       |
| `FR-PII-03` `FR-PII-03a` `FR-PII-03b` `FR-PII-03c` `FR-PII-03d` `FR-PII-03e`            | 利用者が挙げた語と、辞書のファイル   |
| `FR-PII-15` `FR-PII-15a` `FR-PII-15b` `FR-PII-15c` `FR-PII-16`                          | 辞書への語の追加と、辞書の一覧       |
| `FR-PII-04` `FR-PII-05` `FR-PII-06` `FR-PII-06a` `FR-PII-06b` `FR-PII-06c` `FR-PII-06d` | 型の決まった値                       |
| `FR-PII-07` `FR-PII-08` `FR-PII-08a`                                                    | 種類ごとの切り替えと、伏せ字の書き方 |
| `FR-PII-09` `FR-PII-09a` `FR-PII-10` `FR-PII-10a`〜`FR-PII-10g`                         | クレジットカードと API キー          |
| `FR-PII-11`〜`FR-PII-11d`                                                               | 右クリックからのファイルの置き換え   |
| `FR-PII-12` `FR-PII-12a` `FR-PII-13` `FR-PII-13a` `FR-PII-13b` `FR-PII-13c`             | 郵便番号と住所                       |
| `FR-PII-14` `FR-PII-14a`                                                                | マイナンバー                         |

## 方式

| 決めごと                           | 理由                                                                                                      |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 送信の直前で置き換える             | 経路ごとに置き換えると、読み取り・言及・探索・端末の出力のどれかを取りこぼす。口を 1 つに絞る             |
| 置き換えは可逆とする               | モデルは伏せ字のまま応答し、その応答でファイルを編集する。戻せないと編集がファイルを壊す                  |
| 対応表はタスクの中だけに持つ       | ディスクへ書くと、伏せた値そのものを保存することになり、伏せた意味が無くなる                              |
| 伏せ字は `{{種類-番号}}` とする    | 区切りが無いと、戻すときに `person-1` が `person-10` の一部に一致する。`<>` は総称型や JSX と重なる       |
| 推定に頼る検出は入れない           | 人名と組織名の自動判定は誤検出が避けられず、誤って伏せるとモデルが読む内容が変わる。第 2 層として別に扱う |
| 公開されているドメイン名は伏せない | 伏せても守るものが無く、`github.com` が伏せ字になると質問の意味が失われる（`FR-PII-06b`）                 |
| 閉じた宛先は伏せない               | `localhost` と `127.0.0.1` は誰のものでもなく、コードの中で意味を持つ値である（`FR-PII-06a`）             |
| 既定では置き換えない               | 置き換えはモデルが読む内容を変える。気づかないうちに挙動が変わる状態を避ける（`FR-PII-01a`）              |

### 何を伏せるか

11 の種類を持ち、種類ごとに切り替えられる（`FR-PII-07`）。

| 種類             | 検出の仕方                                                 | 伏せ字                              |
| ---------------- | ---------------------------------------------------------- | ----------------------------------- |
| 挙げた語         | 設定に書いた語と、辞書のファイルの語を照合する             | `{{person-001}}` `{{org-001}}` ほか |
| メールアドレス   | 書式で照合する                                             | `{{email-001}}`                     |
| 電話番号         | 日本国内の書き方で照合する                                 | `{{phone-001}}`                     |
| ホスト名         | 公開でない TLD と、単一ラベルのホスト名を照合する          | `{{host-001}}`                      |
| IP アドレス      | グローバルの IPv4 の先頭 2 オクテットを照合する            | `{{ip-001}}`                        |
| クレジットカード | 桁の並びを照合し、Luhn 検査に通ったものだけを採る          | `{{card-001}}`                      |
| マイナンバー     | 12 桁を照合し、検査用数字が合うものだけを採る              | `{{mynumber-001}}`                  |
| API キー         | 既知の接頭辞の一覧で照合する                               | `{{secret-001}}`                    |
| 語に続く値       | `password` `secret` `token` `api key` の後ろの値を照合する | `{{secret-001}}`                    |
| 郵便番号         | `〒` が付く形。付かない形は語が前にあるときだけ            | `{{zip-001}}`                       |
| 住所             | 都道府県名か市区町村名から始まり、番地を含む並び           | `{{address-001}}`                   |

**種類の名前は英字にする。** 多バイトの文字はモデルが写し損ねることがあり、写し損ねると
元の値へ戻せない。

辞書は 1 行 1 語で、タブの後ろに種類を書ける。`田中太郎<TAB>person` と書けば
`{{person-001}}` になる。書ける種類は `person` と `org` で、書かなければ `{{term-001}}` に
なる。種類は伏せ字の見え方を決めるだけで、照合の仕方は変わらない。

**挙げた語がいちばん確実である。** 社名も顧客名も氏名も、利用者は自分の環境で何が危ないかを
知っている。文字列が確定しているので誤検出が起きない（`FR-PII-03`）。辞書のファイルを
指せるようにしてあるので、チームで 1 つの辞書を共有できる（`FR-PII-03b`）。

辞書は 1 行 1 語で、`#` で始まる行と空行は読み飛ばす（`FR-PII-03c`）。読み取りに失敗
しても、ほかの種類の置き換えは続ける（`FR-PII-03d`）。辞書が無いことを理由に、
メールアドレスの伏せ字まで止めない。

### IP アドレスは、割り当て先だけを伏せる

プライベート範囲（`10.` `172.16.`〜`172.31.` `192.168.`）は伏せない（`FR-PII-06c`）。
誰のものでもなく、コードの中で意味を持つ値である。

グローバルの IPv4 は、割り当て先を表す先頭 2 オクテットだけを伏せる（`FR-PII-06d`）。
`203.0.113.5` は `{{ip-001}}.113.5` になる。**伏せた部分そのものを伏せ字にする。**
`x.x.113.5` のように書き換えると元へ戻せず、モデルが書き戻した設定ファイルが壊れる。

### 辞書の文字符号化を判別する

辞書が Shift_JIS で保存されていることがある。UTF-8 として読むと文字化けし、**1 件も
一致しないまま「伏せているつもり」になる**（`FR-PII-03e`）。UTF-8 として厳密に読み、
失敗したら Shift_JIS として読む。Shift_JIS の多バイトの並びは UTF-8 として妥当に
ならないので、この順で判別できる。ASCII だけの辞書はどちらで読んでも同じ結果になる。

依存は足さない。`TextDecoder` が `shift_jis` を扱える。

### 検査で絞る

**クレジットカード番号は Luhn 検査に通ったものだけを伏せる**（`FR-PII-09a`）。桁数だけで
拾うと、注文番号やタイムスタンプまで伏せてしまう。検査すると、誤って拾う割合が
1 桁下がる。

**マイナンバーは検査用数字で絞る**（`FR-PII-14a`）。12 桁の最下位が検査用数字で、
総務省令の定義に従って計算できる。ただし 11 で割った余りから決まるので、でたらめな
12 桁でも 11 回に 1 回は通る。Luhn と同程度の絞り込みだと承知して使う。

**API キーは既知の接頭辞で照合する**（`FR-PII-10a`）。`sk-` `ghp_` `github_pat_` `AKIA`
`xoxb-` `AIza` のような形である。文字の偏り（エントロピー）だけで判定すると、git の
ハッシュ、base64 の資産、最小化したコードまで伏せてしまい、モデルが読むコードが壊れる。
接頭辞で絞れば、取りこぼしは出るが、誤って伏せることは起きない。

**接頭辞を持たない鍵は、語を手がかりに拾う。** 社内で作った鍵には決まった接頭辞が無い。
`password` `secret` `token` `api key` といった語の後ろに来る値を伏せる（`FR-PII-10b`）。
語そのものは残すので、何の値が伏せられたかが読める（`FR-PII-10c`）。

**ラベルの書き方は揺れる。** `api_key` `apiKey` `api-key` `API_KEY` `x-api-key` `apikey`
は同じものを指す。区切り（`-` `_` `.` 空白）と英字の大文字小文字の違いを吸収して照合する
（`FR-PII-10e`）。既定のラベルは次のとおりで、利用者が語を足せる（`FR-PII-10g`）。社内で
使う語まで先に並べておくことはできない。

```
password  passwd  pwd  secret  token  api key  apikey  access key  access token
auth token  client secret  private key  credential
```

`Authorization` の `Bearer` と `Basic` に続く値も同じ扱いにする（`FR-PII-10f`）。ラベルと
値の間に来るものが `:` でも `=` でも空白でも、形は同じである。

値は 8 文字以上の英数字と `-` `_` に限る（`FR-PII-10d`）。`.` と `/` を含むものは値と
見なさない。`password = process.env.PASSWORD` のようなコードの参照まで伏せると、モデルが
読むコードが壊れるためである。

### 辞書は使いながら育てる

**主な導線はエディタの右クリックである**（`FR-PII-15`）。文書を読んでいて伏せられて
いない社名を見つけたら、選んでその場で足す。マスクを実行した直後に「これが伏せられて
いない」と気づくことがいちばん多いので、その場で足せることに価値がある。

足す先の辞書と種類はその都度選ぶ（`FR-PII-15a`）。辞書が 1 つも設定されていなければ、
既定の場所に作る（`FR-PII-15b`）。

**Shift_JIS の辞書へは書き足さない**（`FR-PII-15c`）。UTF-8 のバイト列を書き足すと、
1 つのファイルに 2 つの符号化が混ざって読めなくなる。読むほうは判別できるが、書くほうは
壊すので止める。

設定の画面には辞書のファイルの一覧を置く（`FR-PII-16`）。語を 1 つずつ並べる表は作らない。
語が増えると設定の画面が使いものにならない。

辞書は 1 つのファイルへ書き出せる（`FR-PII-17`）。設定に直接書いた語と、辞書のファイルの
語をまとめる（`FR-PII-17a`）。書き出しは UTF-8 で行い、同じ語は 1 つにまとめる
（`FR-PII-17b`）。チームへ渡すときに、設定と辞書のどちらに書いたかを気にせずに済む。

**書き出したファイルは、伏せたい語だけを集めたものである。** 中身は社名と顧客名と氏名に
なるので、置き場所は利用者が選ぶ。

### 伏せる語は、設定の書き出しから除かない

API キーは書き出しから除いてある（`NFR-SEC-06`）。伏せる語は除かない（`FR-PII-18`）。

**危ないのは語そのものではなく、語と文章が結びつくことである。** 語の一覧だけなら、誰の
名前かは分かっても、その人が何をしていたかは分からない。API キーは一覧だけで使えてしまう
ので、扱いが違う。

除くほうには実害がある。設定を新しいマシンへ移したとき、語だけが移らず、**伏せている
つもりで一致しなくなる**。この機能でいちばん避けたい失敗である。

### 可逆にする

同じ値には同じ伏せ字を割り当てる（`FR-PII-02`）。`taro@corp.example` が 3 か所に出てくる
なら、3 か所とも `{{email-001}}` になる。別の値なら `{{email-002}}` になる。同じ値に別の
番号を割り当てると、モデルは別人だと読む。番号は種類ごとに 1 から振る。

応答が返ったら、ファイルへ書き戻す前に元の値へ戻す（`FR-PII-02a`）。対応表はタスクの
中だけで保持し、ディスクへは書かない（`FR-PII-02b`）。

### 切り替えと件数

**シークレットモード**として、会話の画面の右下にあるボタンで切り替える（`FR-PII-01b`）。
設定の画面まで開かずに、送る直前に決められる。

置き換えた件数は要求ごとに示す（`FR-PII-01c`）。件数が 0 のまま進んでいれば、設定が
効いていないことに気づける。

### 郵便番号と住所は、始まりを手がかりにする

`〒123-4567` は確実に取れる（`FR-PII-12`）。`〒` の無い `123-4567` は電話番号や品番と
重なるので、`郵便番号` `zip` `postal` のような語が前にあるときだけ採る（`FR-PII-12a`）。
語を手がかりにする点は、鍵の検出と同じ考え方である。

住所は**地名が閉じた一覧である**ことを使う。47 都道府県と約 1,700 の市区町村は、
総務省の全国地方公共団体コードとして公開されている。数十 KB なので同梱する
（`FR-PII-13b`）。伏せるための照合で外部へ取得しに行くのは本末転倒である。

都道府県名または市区町村名から始まり、番地（`1-2-3` `丁目` `番` `号`）へ至る並びを
1 つのまとまりとして採る（`FR-PII-13a`）。**番地を含まない並びは採らない**
（`FR-PII-13c`）。「東京都の人口」も「中央区の面積」も番地が無いので採らない。
「中央区銀座 1-2-3」は採る。

市区町村名には「南区」「中央区」のように普通の語と重なるものがあるが、番地を条件に
すれば残らない。

### 2 つの口から使う

検出の層は 1 つで、使い道が 2 つある。

| 口                     | 値の残り方         | 元へ戻せるか               | 守る範囲         |
| ---------------------- | ------------------ | -------------------------- | ---------------- |
| 右クリックで置き換える | ファイルから消える | 戻せない（取り消しと git） | 実行したファイル |
| 送信の直前に置き換える | ファイルには残る   | 戻せる                     | 送る内容すべて   |

**右クリックのほうが確実で、送信時のほうが漏れにくい。** 右クリックは値そのものを消すので、
以降どの経路からも出ない。ただし実行を忘れたファイルは素通りする。送信時は忘れても働くが、
ファイルには値が残る。

右クリックの置き換えは対応表を持たない（`FR-PII-11d`）。持てば、その対応表が伏せた値を
抱えることになり、伏せた意味が無くなる。元へ戻す手段は、編集の取り消しと git に任せる
（`FR-PII-11c`）。

メニューの名前は「このファイルの機密情報をマスクする」とする（`FR-PII-11`）。置き換える
前に、種類ごとの件数を示して実行を選ばせる（`FR-PII-11b`）。戻せない操作を
確認なしで行わない。選択している範囲があるときは、その範囲だけを対象にする
（`FR-PII-11a`）。

## 制約

- 置き換えはモデルが読む内容を変える。伏せた値に依存する質問（「この IP につながらない
  のはなぜか」）には答えられなくなる。
- 辞書の語の照合は、英字の大文字と小文字を区別しない（`FR-PII-03a`）。日本語には
  大文字と小文字の区別が無いため、この規則は英字にだけ働く。
- 伏せ字の番号はタスクごとに振り直す。同じ値でも、別のタスクでは別の番号になる。

## 危険なところ

**戻し損ねるとファイルが壊れる。** モデルが伏せ字を含む内容を書き戻したとき、戻す処理が
漏れると `{{email-001}}` という文字列がファイルへ書かれる。書き戻す経路は編集のツールに
集まっているので、そこを通らない経路を作らないこと。

**伏せ字に見える文字列が元から入っていることがある。** `{{person-001}}` と書かれたファイルを
読むと、戻す処理が誤って別の値へ置き換える。伏せ字は、その回に実際に割り当てたものだけ
を戻す。割り当てていない番号には触らない。

**種類を全部切っても、ボタンは有効のままになり得る。** その状態では 1 件も伏せられない
のに、利用者は伏せているつもりになる。件数の提示（`FR-PII-01c`）はこの取り違えを
見つけるためにある。

## できていないこと

- 人名と組織名の自動判定は入れていない。形態素解析と固有名詞の辞書による第 2 層は別に
  扱う。いまは利用者が挙げた語だけが、名前を伏せる手段である。
- 画像は対象外である。ファイルの中身の文字列だけを見る。
- IPv6 は対象外である。IPv4 だけを見る。
- Shift_JIS の辞書は読めるが、書き足せない。手で足すか、UTF-8 で保存し直す。
- git の履歴は対象外である。右クリックで置き換えても、それ以前の commit には値が残る。
- 町域（`神南` `丸の内`）の一覧は持たない。市区町村までで照合し、その後ろは番地まで
  まとめて採る。
- 自社の公開ドメインは伏せない。伏せたい場合は、挙げる語として書く。
