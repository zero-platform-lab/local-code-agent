# LLM への接続

接続先を OpenAI 互換の 1 種類に絞ったうえで、実装ごとの差を設定で吸収する。
**「OpenAI 互換」を名乗る実装は、対応する要求の形が揃っていない。**

## 目的

| 満たす要件                                                           | 内容                                                         |
| -------------------------------------------------------------------- | ------------------------------------------------------------ |
| `FR-PROV-01` `FR-PROV-01a`                                           | 接続先を OpenAI 互換に限る。試験用の接続先を別に持つ         |
| `FR-PROV-02` `FR-PROV-02a` `FR-PROV-02b`                             | 接続先の登録、プロファイルの切り替え、環境変数からの読み込み |
| `FR-PROV-03` `FR-PROV-03a`                                           | Azure OpenAI と Azure AI Inference                           |
| `FR-PROV-04` `FR-PROV-05`                                            | 追加のヘッダーと、ストリーミングの切り替え                   |
| `FR-PROV-06` `FR-PROV-06a` `FR-PROV-07` `FR-PROV-07a`                | 推論の深さと Responses API                                   |
| `FR-PROV-08`                                                         | 温度と、出力の上限を送るかどうか                             |
| `FR-PROV-09` `FR-PROV-09a` `FR-PROV-09b` `FR-PROV-09c` `FR-PROV-09d` | 疎通の確認                                                   |
| `FR-PROV-10`                                                         | トークンの消費量と費用の集計                                 |

| `NFR-CMP-01` `NFR-CMP-01a`                                           | 実装ごとの差を設定で吸収する                                 |

## 決めごと

実装は `src/api/providers/openai.ts`。OpenAI 互換と試験用の 2 つ以外は、接続の構築の
時点で例外にして拒否する。スタブを残さない。

### 実装ごとの差を吸収する設定

| 設定                           | どの差を吸収するか                             |
| ------------------------------ | ---------------------------------------------- |
| Azure を使う                   | 認証のヘッダーの名前と、URL の組み立てが変わる |
| Responses API を使う           | 推論とツールを併用できない接続先がある         |
| ツール併用時に推論の深さを送る | 併用に対応した接続先で、深さを送れるようにする |
| ストリーミング                 | ストリーミングに対応しない接続先がある         |
| 出力の上限を送る               | 上限の指定を受け付けない接続先がある           |

Azure AI Inference は、URL のドメインから自動で判別する。

### 疎通の確認は 2 回投げる

1 回目はツールを付けずに、2 回目は付けて投げる。差はツールだけなので、2 回目だけが
詰まれば原因を 1 つに絞れる。上限の時間は実際のリクエストと同じにする。疎通の確認
だけ短くすると、応答の遅い接続先を「繋がらない」と誤って判定する。

診断には、実際に送る URL・ヘッダーの名前と長さ・本文をそのまま載せる。認証に使う
ヘッダーの値だけを伏せる。**送信内容が分からないまま切り分けを進めさせない。**

proxy の解決は、実際のリクエストと同じ経路を使う。別々に引くと、診断が実態とずれる。

## 制約

- 接続先の設定は VS Code の設定ファイルへ置かない。拡張の保存先に持ち、API キーは
  SecretStorage へ置く。
- 費用の集計は、接続先が使用量を返す場合にだけできる。
- Responses API に対応しない接続先では、その設定を拒否する。

## 危険なところ

- **疎通の確認と実際のリクエストで、別々の設定を引かない。** 引くと、確認では成功するのに
  実際には失敗する状態になる。
- 診断へ載せる値を増やすときは、伏せる対象を併せて確かめる。診断はそのまま外部へ
  渡される。

## 確かめ方

| 何を                                    | どこで                                                                  |
| --------------------------------------- | ----------------------------------------------------------------------- |
| 対応しない接続先を拒否すること          | `src/api/providers/__tests__/openai.spec.ts`                            |
| 認証のヘッダーが伏せられること          | `src/api/providers/__tests__/testOpenAiConnection.diagnostics.spec.ts`  |
| 2 回目だけの失敗を区別すること          | 同上                                                                    |
| 疎通の確認と実際で同じ proxy を使うこと | `src/api/providers/__tests__/testOpenAiConnection.proxy-source.spec.ts` |
| Responses API の経路                    | `src/api/providers/__tests__/responses-api.integration.spec.ts`         |
| 推論とツールの併用                      | `src/api/providers/__tests__/reasoning-none.integration.spec.ts`        |
| Azure の経路                            | `src/api/providers/__tests__/openaiAzure.integration.spec.ts`           |

## できていないこと

- 費用の集計は、使用量を返さない接続先では動かない（`FR-PROV-10`）。
- 実際のエンドポイントへ要求を送る試験は、環境変数の背後に置いてあり、品質ゲートでは
  実行しない（`FR-PROV-09`）。
