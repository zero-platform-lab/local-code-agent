# タスクの管理と保存

タスクの履歴・保存先・書き出し・worktree を扱う。本製品が保持する情報の置き場所を
決める場所でもある。

## 目的

| 満たす要件                                                              | 内容                                       |
| ----------------------------------------------------------------------- | ------------------------------------------ |
| `FR-TASK-01` `FR-TASK-02` `FR-TASK-03`                                  | 履歴からの再開、2 つの会話の保持、書き出し |
| `FR-TASK-04` `FR-TASK-04a` `FR-TASK-05`                                 | worktree の操作と、画像の保存先            |
| `FR-DAT-01` `FR-DAT-02` `FR-DAT-03` `FR-DAT-04` `FR-DAT-05` `FR-DAT-06` | 保持する情報とその場所                     |
| `FR-DAT-07` `FR-DAT-08`                                                 | 設定の検証と、保存先の変更                 |
| `FR-DAT-10` `FR-DAT-10a` `FR-DAT-12`                                    | 削除と、画面へ送るデータの中身             |
| `FR-DAT-11` `FR-DAT-11a` `FR-DAT-11b`                                   | 書き出しに秘密を含めるかを選ぶ             |
| `NFR-REL-05`                                                            | 設定の一部が壊れていても起動する           |
| `NFR-CMP-02`                                                            | 版を上げても、保存済みの設定を読み込める   |

ユースケースは UC-14（履歴から再開する）・UC-15（書き出す）・UC-16（worktree を使う）。

### 扱わないもの

| 対象                                 | どこにあるか                     |
| ------------------------------------ | -------------------------------- |
| チェックポイントのリポジトリの作り方 | [checkpoints.md](checkpoints.md) |
| 接続先の設定の中身                   | [provider.md](provider.md)       |

## 方式

タスクの保持は `src/core/task-persistence/`、履歴の管理は `src/core/webview/` の
コントローラ群、設定の入口は `ContextProxy` の 1 か所。

### 会話は 2 本持つ

| 会話           | 用途                                           |
| -------------- | ---------------------------------------------- |
| LLM へ送る履歴 | 要約と切り詰めの対象                           |
| 画面へ出す履歴 | 利用者が読む記録。チェックポイントの目印を含む |

2 本を分けているのは、要約で LLM 側の履歴が短くなっても、利用者が読む記録は残す
ためである。

### 設定は検証してから読み込む

スキーマで検証し、失敗した値は既定値で置き換える。**設定の一部が壊れていても、拡張は
起動する。** 起動しないと、設定を直す画面も開けない。

### 書き出しに秘密を含めるかは、書き出す前に選ばせる

**既定は「含めない」。** 設定を別のマシンへ移す、人に渡すという普通の使い方では鍵が
要らない。含める場合だけ、平文で入ることを承知したうえで選ぶ。選ばずに閉じたら、
保存ダイアログを出さずに取りやめる。

含めない場合は `SECRET_STATE_KEYS` の 3 つを落とし、追加ヘッダーの値を空にする。
**ヘッダーの名前は残す。** 名前まで消すと、読み込んだ側は何を入れ直せばよいか分からない。
`convertHeadersToObject` は値が空でもキーを残すので、設定画面には空の行として出る。

含めた場合は、書き出した後に平文である旨を伝える。黙って出さない。

**暗号化は採らなかった。** 鍵を SecretStorage に置くとそのマシンでしか復号できず、
書き出しの用途（別のマシンへ移す、壊れたときに備える）のどちらにも使えない。
パスフレーズを求める形は、何を入れればよいか分からない入力欄になる。
含めないことを選べれば、守るべきものがそもそもファイルに入らない。

画面へ送るデータには、展開済みの環境変数を含めない。

### タスクを削除したら、付随するものも消す

タスクを削除したときは、会話の記録とチェックポイントのリポジトリも併せて消す。
消さないと、保存先に使われないリポジトリが残り続ける。

## 制約

- 保存先は利用者が変更できる。変更したときの移行は、利用者が行う。
- 履歴の保存期間を定めていない。
- worktree の操作は git に委ねる。本製品は一覧と作成と削除だけを行う。

## 危険なところ

- **削除の対象を増やすときは、ワークスペースの外だけを消すことを確かめる。**
  チェックポイントの作業ツリーはワークスペースを指している。
- 書き出したファイルは共有される。**秘密の項目を足したら、落とす側にも足す。**
  落とす対象は `SECRET_STATE_KEYS` と追加ヘッダーの 2 つだけである。

## 確かめ方

| 何を                           | どこで                                                         |
| ------------------------------ | -------------------------------------------------------------- |
| 履歴の保持と再開               | `src/core/webview/__tests__/ClineProvider.taskHistory.spec.ts` |
| 削除で付随するものが消えること | `src/core/webview/__tests__/TaskDeletionController.spec.ts`    |
| 会話 2 本の保持                | `src/core/task/__tests__/TaskMessageStore.spec.ts`             |
| 既定で秘密が入らないこと       | `src/core/config/__tests__/importExport.spec.ts`               |
| 含めたときだけ警告が出ること   | 同上                                                           |
| worktree の操作                | `src/core/webview/__tests__/worktreeHandlers.spec.ts`          |

## できていないこと

- 履歴とチェックポイントの保存期間を定めていない（`requirements.md` の 5.2）。
- 保存先を変えたときの移行の手段が無い（`FR-DAT-08`）。
