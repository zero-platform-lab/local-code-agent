# ツールの提示と制限

LLM が呼び出せる操作の一覧を決める仕組みである。**提示する側と、呼び出しを受けて
許可を判定する側の 2 か所があり、両方が同じ判定でなければならない。**

## 目的

| 満たす要件                                                       | 内容                                                                        |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `FR-TOOL-01` `FR-TOOL-02` `FR-TOOL-03`                           | ツールをネイティブの定義として渡し、5 つのグループと常時利用の 6 件に分ける |
| `FR-TOOL-04` `FR-TOOL-05`                                        | 役割モードと自律モードによる制限。提示と拒否の双方で効かせる                |
| `FR-TOOL-06` `FR-TOOL-07` `FR-TOOL-08` `FR-TOOL-09` `FR-TOOL-10` | 個別に外す設定と、条件付きで提示するツール                                  |
| `FR-TOOL-11` `FR-TOOL-12`                                        | 未知の名前の拒否と、別名の解決                                              |

ユースケースは UC-13（提示するツールを絞る）。

### 扱わないもの

| 対象                 | どこにあるか                                                                                             |
| -------------------- | -------------------------------------------------------------------------------------------------------- |
| 各ツールの動作       | [file-access.md](file-access.md)・[editing.md](editing.md)・[command-execution.md](command-execution.md) |
| 実行してよいかの承認 | [approval.md](approval.md)                                                                               |
| MCP のツールの提示   | [mcp-servers.md](mcp-servers.md)                                                                         |

## 方式

ツール名の正準の出所は `packages/types/src/tool.ts` の `toolNames` である。
ツール名の一覧は `packages/types/src/tool.ts` にある。グループの定義と常時利用の一覧は
`src/shared/tools.ts` の `TOOL_GROUPS` と `ALWAYS_AVAILABLE_TOOLS`。判定は
`src/core/tools/validateToolUse.ts`。

**`src/core/tools/` のファイルの数はツールの数ではない。** 基底クラスと補助が混ざる。
数えるときは `toolNames` を数える。

### 提示と拒否を分けて両方に効かせる

提示は `src/core/prompts/tools/filter-tools-for-mode.ts` が、拒否は `validateToolUse.ts` が
行う。片方だけを直すと、提示していないツールを呼ばれたときに実行されてしまう。

### 読み取りだけを許す自律モードは、グループ単位で拒否する

`plan` では edit グループと command グループを、役割モードに関わらず拒否する。
mcp グループは読み取りのため許す。サブタスクは別の設定で制御し、読み取りだけを許す
状態を引き継ぐ。

### 条件付きの提示

| ツール                | 提示する条件                         |
| --------------------- | ------------------------------------ |
| `web_fetch`           | 利用者が明示的に有効にした場合のみ   |
| `codebase_search`     | コードインデックスが有効な場合のみ   |
| `run_slash_command`   | 実験機能を有効にした場合のみ         |
| 編集ツールの別名 4 件 | モデルの設定で明示的に挙げた場合のみ |

`web_fetch` を既定で外しているのは、通信の制限された環境で失敗し、その失敗が
その対処にタスクが費やされるためである。

## 制約

- 別名は正式名へ解決してから判定する。解決の表は `TOOL_ALIASES` の 1 か所に持つ。
- MCP のツールは `mcp_` で始まる名前で届くため、実在するツール名の一覧では判定できない。
  接頭辞で通したうえで、MCP 側が存在を確かめる。
- グループの単位より細かい制限は持たない。ファイルの種別による編集の制限は撤去した
  （`requirements.md` の 1.6）。

## 危険なところ

- **提示の一覧と拒否の判定がずれると、テストも型検査も成功したまま穴が開く。** 変更は
  必ず両方へ加える。
- 役割モードが解決できない場合、判定は偽を返す。常時利用の 6 件以外がすべて使えなくなる
  （[modes.md](modes.md)）。

## 確かめ方

| 何を                             | どこで                                                           |
| -------------------------------- | ---------------------------------------------------------------- |
| 常時利用が 6 件であること        | `src/core/tools/__tests__/validateToolUse.spec.ts`               |
| 読み取りだけを許すモードでの拒否 | `src/core/tools/__tests__/validateToolUse.plan.spec.ts`          |
| 提示の一覧の絞り込み             | `src/core/prompts/tools/__tests__/filter-tools-for-mode.spec.ts` |
| 別名の解決                       | `src/core/tools/__tests__/validateToolUse.spec.ts`               |
| 一覧の件数が文書と合うこと       | `scripts/check-docs.mjs`                                         |

## できていないこと

- 同じ機能のツールに別名が複数ある（`FR-TOOL-10`）。残すかどうかは
  `requirements.md` の 5.2 に未確定として置いた。
- 利用者が個別にツールを外す設定に、画面が無い（`FR-TOOL-06`）。
