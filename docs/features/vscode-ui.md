## 方式

拡張ホストは `src/`、画面は `webview-ui/`。両者は `postMessage` だけで通信し、
画面の状態は 1 つの保持場所に集約する。

### 画面はセカンダリサイドバーへ置く

GitHub Copilot と同じ配置にする。この配置は VS Code の `1.106.0` 以上を要する。
**設定の名前の大文字小文字を誤ると、黙って無視されてエクスプローラーへ移る。**

### 追加ヘッダーの値は、名前に関わらず伏せる

追加ヘッダーの値は API キーであることがある。既定で伏せ、行ごとに目のアイコンで
一時的に出す。**名前で秘密かどうかを判定しない。** `Authorization` や `api-key` は
拾える。しかし社内 proxy の `X-Gateway-Token` のような独自の名前は検出できず、
漏れる側へ倒れる。診断の側も同じ判断をしている（[provider.md](provider.md)）。

行を消したら、出している行をすべて閉じる。行を消すと以降の位置がずれるため、
閉じないと別の行の値が出たままになる。

### 設定の画面は、保存するまで書き込まない

入力は画面の内側の下書き（`cachedState`）へ結び付け、保存の操作で初めて設定の保持者へ書き込む。
入力の途中の値が実行に使われることを防ぐ。

### 識別子は実行時のパッケージ名と一致させる

コマンドとビューは実行時に「パッケージ名 + 識別子」として登録される。配布ビルドは
パッケージ名を差し替えるため、生成する定義の側も併せて差し替える。**不一致は
「コマンドが見つからない」・押しても反応しない設定のボタン・初回の起動の繰り返しとして
現れる。**

### 配布する成果物は圧縮する

圧縮しないと拡張ホストの読み込みが目に見えて遅くなる。配布ビルドの手順は、別の
パッケージから `src/` を読むため、ビルドの結果を再利用しない設定にする。再利用すると
古い出力が返る。

## 制約

- 接続先の設定は VS Code の設定ファイルへ置けない。置けるのは実行の制御に関わる
  キーだけである。
- Webview は外部のドメインへ接続しない。読み込む資源は拡張自身のものに限る。
- 設定の書き出しに秘密を含めるかは、書き出す前に利用者が選ぶ（[tasks.md](tasks.md)）。

## 危険なところ

- **識別子の不一致は、型検査もテストも成功したまま起きる。** 一致を確かめる試験が
  `packages/build` にある。
- 画面の状態を細かく送ると、更新のたびに再描画が走る。状態は 1 つのまとまりで送る。

## 確かめ方

| 何を                             | どこで                                                                             |
| -------------------------------- | ---------------------------------------------------------------------------------- |
| 起動・画面の表示・コマンドの登録 | `apps/vscode-e2e/src/suite/extension.test.ts`                                      |
| 識別子の一致                     | `packages/build/src/__tests__/index.test.ts`                                       |
| 状態の組み立て                   | `src/core/webview/__tests__/buildExtensionState.spec.ts`                           |
| ヘッダーの値が伏せられること     | `webview-ui/src/components/settings/providers/__tests__/OpenAICompatible.spec.tsx` |
| 設定の書き出しと読み込み         | `src/core/webview/__tests__/settingsMessageHandlers.spec.ts`                       |
| 成果物の大きさ                   | `pnpm bundle:internal` の出力を測る                                                |

## できていないこと

- 画面の実機での確認は、手順があるだけで自動化していない（`FR-UI-20`）。
- 設定のタブの分け方に、まだ揺れがある（`FR-UI-21`）。
