## 1. はじめに

### 1.1 目的

**本製品は、VS Code の拡張として動作する AI コーディングエージェントである。**
利用者の指示を受け取り、LLM への送信とツールの実行を反復して、ワークスペースのコードを
調査し変更する。実装は TypeScript による。

本書は、本製品が備えるべき機能および品質を定める。

### 1.2 適用範囲

**本製品は Roo Code のフォークである。Roo Code が備える機能を、要件を洗い出す出発点とする。**
実際に使われている拡張であり、必要な機能の範囲が実証されているためである。

そのうえで、本製品に何を備えるかは本書で決める。

|                     |                                            |
| ------------------- | ------------------------------------------ |
| 採用したもの        | 3.2 の要件                                 |
| 採用しなかったもの  | 1.6                                        |
| Roo Code に無いもの | 3.2 のうち「Roo Code」欄が **独自** のもの |

**Roo Code の実装方式は再現しない。** 画面の構成、プロンプトの文面、内部の表現形式、
設定の持ち方は本製品で定める。

3.2 の表の「Roo Code」欄は、その要件の出発点を示す。

| 表記                                | 意味                                                              |
| ----------------------------------- | ----------------------------------------------------------------- |
| `設定キー` `ツール名` `コマンド ID` | Roo Code の当該箇所を出発点とした                                 |
| 継承                                | Roo Code から継いだ。本製品が手を入れた記録は無い                 |
| 作り直し                            | Roo Code にも同じ要件があるが、本製品が実装に手を入れた記録がある |
| **独自**                            | Roo Code に無い。本製品で定めた                                   |

**「継承」は、変えていないことの証明ではない。** リポジトリを移設した際に履歴を
1 コミットへまとめたため、移設より前の改変は git から追えない。「作り直し」と判定した
根拠は次の 3 つに限られ、そのいずれも無いものを「継承」としている。

| 根拠         | 内容                                                                                                                              |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| 移設後の変更 | `f047812` 以降の変更（PR #1 から #45）                                                                                            |
| 実装の注記   | 実装に、構造または挙動を変えた記録が日本語で書かれていること。Roo Code の注記は英語なので、日本語の注記は本製品が書いたものである |
| 文書の記録   | `README.md` と `AGENTS.md` に書かれた改変                                                                                         |

**網羅率のために書いた「到達不能」の注記は、根拠に数えない。** 分岐が踏めないことを
書き残しただけで、挙動を変えていないためである。

### 1.4 製品の機能

本製品が扱う対象を次のとおり整理する。

| 対象                   | 説明                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| タスク                 | 利用者の 1 つの指示から完了までの単位。入れ子にできる                |
| ツール                 | LLM が呼び出せる操作。ファイルの読み書き、探索、コマンドの実行など   |
| 自律モード             | ツールの実行に承認を求めるかどうかの設定。**利用者だけが変えられる** |
| 役割モード             | LLM に与える役割文と、使用できるツールグループの組                   |
| プロバイダプロファイル | 接続先の LLM の設定の組。役割モードごとに割り当てられる              |
| チェックポイント       | 編集の直前のワークスペースの記録。任意の時点へ戻せる                 |
| MCP サーバ             | 外部プロセスが公開するツールとリソースの提供元                       |
| 拡張ポイント           | ルール・スキル・スラッシュコマンドによる指示の追加                   |

利用者が本製品で行うことを次のとおり整理する。3.2 の要件は、いずれかに対応する。

#### 1.4.1 コードを変更する

|       | できること                                              |
| ----- | ------------------------------------------------------- |
| UC-01 | 指示を出し、ワークスペースのコードを書かせる            |
| UC-02 | 変更を確定する前に差分を読み、承認または破棄する        |
| UC-03 | 加えられた編集を、任意の時点まで丸ごと戻す              |
| UC-04 | 編集で新しく発生したエラーを LLM へ返し、続けて直させる |

#### 1.4.2 調査する

|       | できること                                        |
| ----- | ------------------------------------------------- |
| UC-05 | コードベースを探索させ、構造と経路を説明させる    |
| UC-06 | コマンドを実行させ、その出力を読ませる            |
| UC-07 | ファイルを変更させずに、計画だけを立てさせる      |
| UC-08 | 外部のツールサーバ（MCP）が公開する機能を使わせる |

#### 1.4.3 制御する

|       | できること                                             |
| ----- | ------------------------------------------------------ |
| UC-09 | 承認を求める範囲を、自律モードで切り替える             |
| UC-10 | 実行してよいコマンドと、してはならないコマンドを定める |
| UC-11 | 本製品が読み書きしてよいファイルを制限する             |
| UC-12 | 実行中のタスクを中断する                               |
| UC-13 | LLM に提示するツールを絞る                             |

#### 1.4.4 引き継ぐ

|       | できること                                       |
| ----- | ------------------------------------------------ |
| UC-14 | 過去のタスクを一覧から再開する                   |
| UC-15 | タスクの内容をファイルへ書き出す                 |
| UC-16 | git の worktree を作り、別の作業を並行して進める |

#### 1.4.5 設定する

|       | できること                                                           |
| ----- | -------------------------------------------------------------------- |
| UC-17 | 接続先の LLM を登録し、疎通を確かめる                                |
| UC-18 | 役割モードごとに接続先を変える                                       |
| UC-19 | プロジェクト固有の指示（ルール・スキル・スラッシュコマンド）を与える |
| UC-20 | MCP サーバを登録する                                                 |
| UC-21 | 画面の表示言語を選ぶ                                                 |

### 1.5 利用者の特性

本製品の利用者は 1 種類である。**ソフトウェアを開発する技術者であり、
VS Code を日常的に使い、ターミナルのコマンドを読める。**

|      | 前提とすること                                   | 前提としないこと                   |
| ---- | ------------------------------------------------ | ---------------------------------- |
| 技能 | VS Code の操作、git、シェル                      | LLM の内部動作の知識               |
| 環境 | 接続できる OpenAI 互換エンドポイントを持つ       | 公開のクラウドサービスに接続できる |
| 判断 | 提示された差分とコマンドの妥当性を自分で判断する | 本製品の出力を無検証で採用する     |

**管理者という役割を設けない。** 設定はすべて利用者自身が行う。組織単位で設定を配る
仕組みも持たない（1.6）。

### 1.6 制限事項

本製品が備えないものを次に挙げる。いずれも意図して備えない。

| 提供しないもの                       | 理由                                                                                                    |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| OpenAI 互換以外の LLM プロバイダ     | 接続先を 1 種類に絞る。Roo Code のプロバイダ実装はスタブを残さず削除した                                |
| テレメトリと利用状況の送信           | 外部への通信を、利用者が設定した宛先だけに限る（3.2.14）                                                |
| ユーザー定義の役割モード             | 未使用のまま構成を複雑にしていた。文面の調整は役割モードの設定画面と `AGENTS.md` で足りる               |
| ファイル種別による編集の制限         | ユーザー定義の役割モードと同時に撤去した。制限はツールグループ単位で行う                                |
| モデルによる役割モードの変更         | 自律モードと同じく、モードの決定は利用者に限る                                                          |
| 音声の読み上げと効果音               | 利用されていなかった                                                                                    |
| ブラウザ操作のツール群               | Roo Code から削除した                                                                                   |
| 単体のコマンドライン実行ファイル     | Roo Code から削除した                                                                                   |
| GitHub Actions による CI             | 非公開リポジトリでは実行時間が課金されるため、削除した（3.6）                                           |
| 組織単位の設定配布                   | 利用者は個人であり、配布の対象が無い                                                                    |
| 役割モードの定義の書き出しと読み込み | ユーザー定義モードと同時に撤去した。変えられるのは `customModePrompts` だけで、設定の書き出しに含まれる |
| 環境変数による接続先の指定           | 接続先の出どころが 2 つになり、`FR-UI-13` と競合する                                                    |
| ほかの拡張からの設定の自動の引き継ぎ | 起動時にほかの拡張の保存領域を探しに行かない。書き出したファイルを読み込む経路はある（`FR-UI-27`）      |
| 自動更新                             | `.vsix` を手で導入する                                                                                  |

| 前提               | 内容                                                                       |
| ------------------ | -------------------------------------------------------------------------- |
| VS Code            | `1.106.0` 以上。セカンダリサイドバーの識別子がこの版から有効になる         |

### 1.8 定義

| 語                     | 意味                                                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------------------- |
| タスク                 | 利用者の 1 つの指示から完了までの単位。会話履歴とチェックポイントを持つ                                       |
| サブタスク             | タスクの中から起動された別のタスク。完了すると親へ結果を返す                                                  |
| ツール実行ループ       | LLM への送信、ツールの実行、結果の再送信を繰り返す動作。本製品の中核                                          |
| 自律モード             | ツールの実行に承認を求めるかどうかの設定。`manual` `autoEdit` `auto` `plan` の 4 種類                         |
| 役割モード             | LLM に与える役割文と、使用できるツールグループの組。`code` と `research` の 2 件                              |
| ツールグループ         | ツールの分類。役割モードはグループ単位で使用範囲を持つ                                                        |
| 自動承認               | 承認を求めずにツールを実行すること。自律モードが対応するトグルを書き換える                                    |
| 差分プレビュー         | 編集を確定する前に、エディタの差分ビューで見せること                                                          |
| チェックポイント       | 編集の直前にワークスペース全体を記録したもの                                                                  |
| シャドウ git           | チェックポイントが使う git リポジトリ。本体をワークスペースの外に置き、作業ツリーだけをワークスペースに向ける |
| 要約                   | 会話履歴が長くなったときに、LLM へ要約させて圧縮する処理                                                      |
| プロバイダプロファイル | 接続先の LLM の設定の組。複数を登録して切り替えられる                                                         |
| コードインデックス     | ソースを分割して埋め込みベクトルにし、意味で探せるようにしたもの                                              |
| 拡張ポイント           | ルール・スキル・スラッシュコマンドによって、利用者が指示を足せる場所                                          |

## 3. 要件

要件には `FR-` で始まる機能要件と、`NFR-` で始まる非機能要件がある。番号に続く
英小文字は、直前の要件を細かく定めた派生である（`FR-LOOP-08a` は `FR-LOOP-08` の派生）。
その派生をさらに分けるときは数字を足す（`FR-EXT-05b1` は `FR-EXT-05b` の派生）。

### 3.1 外部インタフェース

#### 3.1.1 利用者インタフェース

### 3.2 機能

#### 3.2.1 ツール実行ループ（LOOP）

| ID            | 要件                                                                                                                                                                                         | Roo Code                         |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| `FR-LOOP-01`  | 本製品は、利用者の指示を LLM へ送信し、LLM が指定したツールを実行し、その結果を会話履歴へ追加して再送信する反復として動作する                                                                | 作り直し                         |
| `FR-LOOP-02`  | 反復は、LLM が `attempt_completion` を返した時点で終了する                                                                                                                                   | `attempt_completion`             |
| `FR-LOOP-03`  | 反復は、関数の再帰ではなく明示的なスタックで実装する                                                                                                                                         | 作り直し                         |
| `FR-LOOP-04`  | 利用者は反復の途中で中断を要求できる。中断はストリームの断片の境界ごとに判定する                                                                                                             | 作り直し                         |
| `FR-LOOP-05`  | 応答の断片は、本文・推論・使用量・ツール呼び出しの種類別に振り分ける                                                                                                                         | 作り直し                         |
| `FR-LOOP-06`  | ツール呼び出しの提示と実行は再入を禁じ、並行して実行しない                                                                                                                                   | 作り直し                         |
| `FR-LOOP-07`  | API がエラーを返した場合は、指数バックオフで再試行し、待機の残りを利用者へ表示する                                                                                                           | 作り直し                         |
| `FR-LOOP-07a` | 再試行しても直らないクライアントエラー（4xx。ただし 429・408・409・425 などの一時的なものと、context-window 超過を除く）は、送信直後もストリーム途中も終端エラーとして表面化し、再試行しない | **独自**                         |
| `FR-LOOP-07b` | API の再試行の回数に上限を設け、超えた場合は終端エラーとして表面化する                                                                                                                       | **独自**                         |
| `FR-LOOP-08`  | LLM の応答が空だった場合は、猶予の回数まで再試行する                                                                                                                                         | 作り直し                         |
| `FR-LOOP-09`  | ツールの実行が連続して失敗した回数が上限に達した場合は、反復を止めて利用者の判断を求める                                                                                                     | `consecutiveMistakeLimit`        |
| `FR-LOOP-10`  | 同一のツールを同一の引数で繰り返し呼び出したことを検出し、反復を止める                                                                                                                       | 作り直し                         |
| `FR-LOOP-11`  | 1 リクエストの応答が所定の時間内に届かない場合は、待機を打ち切ってエラーとして利用者へ表示する                                                                                               | **独自**                         |
| `FR-LOOP-11a` | 待機の打ち切りは、応答の全体だけでなく、ストリームの断片と断片の間隔にも適用する                                                                                                             | **独自**                         |
| `FR-LOOP-11b` | 待機の上限は `openai-agent.apiRequestTimeout`（秒、既定 600）で定める。0 は上限を設けないことを表す                                                                                          | **独自**                         |
| `FR-LOOP-11c` | 待機の打ち切りは、下層への中断要求の成否に依存せず成立する                                                                                                                                   | **独自**                         |
| `FR-LOOP-12`  | LLM は、サブタスクを起動して作業を委譲できる。サブタスクの完了時に結果を親へ返す                                                                                                             | `new_task`                       |
| `FR-LOOP-12a` | サブタスクの起動には、承認を求めるかどうかの設定を別に持つ                                                                                                                                   | `alwaysAllowSubtasks`            |
| `FR-LOOP-13`  | 連続するリクエストの間に、利用者が定めた待機時間を置ける                                                                                                                                     | `rateLimitSeconds`               |
